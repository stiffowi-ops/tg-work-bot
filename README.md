# WorkHub · Маршрутизация

Ветка `main` содержит согласованную версию Telegram Mini App **V9.6.2-admin-cards**. Для Bothost выберите Docker, корневой `Dockerfile` и контекст сборки `.`. Образ запускает Go-сервис через встроенный `docker-entrypoint.sh`.

## Запуск и постоянные данные

- Подключите существующий постоянный том к `/app/data` и задайте `DATA_DIR=/app/data`. При пересоздании контейнера подключайте тот же том. Если рабочий том уже подключён к `/app/runtime`, оставьте этот путь и явно укажите его в `DATA_DIR`.
- Передайте `BOT_TOKEN`, `WORK_CHAT_ID` и, для администраторов, `ADMIN_USER_IDS`. Сервис слушает порт из `PORT`. Значение по умолчанию — `8080`, на хостинге можно использовать назначенный порт.
- Запускайте один экземпляр WorkHub на том. В журнале запуска виден фактический путь к данным. Для проверки версии откройте `/api/health`.

| Что хранится | Путь внутри тома |
| --- | --- |
| Профили и закладки | `employees.json` |
| Описание и список материалов проекта | `data/projects/<проект>/content.json` |
| Загруженные документы, изображения и видео | `data/projects/<проект>/files/<id>` |

Сохраняйте резервную копию всего тома. Для согласованной копии остановите запись на время снимка. Новые версии используют тот же формат и расположение файлов. Инструкции по доступу и работе с материалами приведены в [WORKHUB.md](WORKHUB.md).

## Отдельный Python-бот

`bot.py` обслуживает команды чата и использует long polling. Если этот сервис уже используется, сохраните его отдельный запуск через `python bot.py`, зависимости из `requirements.txt`, действующие `DATABASE_PATH` (или `DB_PATH`) и `STORAGE_DIR`. SQLite и вложения этого сервиса имеют собственные пути. Для развёртывания WorkHub используется Dockerfile, указанный выше.
